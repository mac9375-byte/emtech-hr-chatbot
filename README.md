# 이엠텍 HR 챗봇 (RAG)

한국어 인사 규정을 근거로 답하는 **로컬 RAG 챗봇 프로토타입**입니다.
외부 API를 호출하지 않고, Ollama 로컬 모델만으로 동작합니다.

> [!IMPORTANT]
> **이 저장소의 인사 문서는 전부 가상 샘플입니다.**
> `data/src`, `data/raw`의 취업규칙·복무규정·복리후생규정·FAQ·신청양식은 이 프로젝트를 위해
> 지어낸 것이며, 회사명과 모든 수치(급여, 휴가 일수, 수당, 대출 금리 등)가 실제와 무관합니다.
> 실제 사내 문서가 아니고, 법령과도 다릅니다. 어떤 용도로도 규정 근거로 쓸 수 없습니다.

## 무엇을 하는가

일반 직원이 "경조휴가는 본인 결혼 시 며칠인가요?"처럼 물으면, 규정 문서에서 근거를 찾아
**출처(문서명·조항·쪽)와 함께** 답합니다. 근거가 없으면 답을 만들지 않고 거부합니다.

| 질문 | 동작 |
|---|---|
| 규정에 있는 내용 | 근거 조항을 인용해 답변 + 출처 표시 |
| 규정 밖 (날씨, 잡담) | LLM 호출 없이 거부 |
| 개인 정보 조회 (내 잔여 연차) | HR팀 안내 |
| 법률 해석·개인별 판단 | HR팀 안내 |

## 구조

프레임워크(LangChain/LlamaIndex) 없이 라이브러리를 직접 조립했습니다.

```
문서(PDF/docx) → 조 단위 청킹 158개 → bge-m3 임베딩 → data/index/
                                                          ↓
질문 → 하이브리드 검색(벡터 + BM25, RRF) → 거리 게이트 → 근거 3개 → gemma3:4b → 숫자 검증 → 답변+출처
```

- **검색** — bge-m3 벡터(numpy 전수 코사인) + BM25(글자 2-gram)를 RRF로 합침
- **청킹** — 제N조/문항/양식 단위. 문서명·조 번호·시행일·쪽을 메타데이터로 보관
- **거부** — 벡터 1위 거리가 `0.50`을 넘으면 LLM을 부르지 않음. 프롬프트에도 같은 지시 병행
- **근거 조립** — 직접 검색된 규정을 FAQ가 인용한 규정보다 먼저 넣음
- **숫자 검증** — 답변 속 숫자가 인용한 근거에 없으면 출처를 옮기거나 거부 (출처 오표기 방지)
- **멀티턴** — 질문 단독 + 직전 질문 결합을 함께 검색해 RRF로 합침

| 구성 | 선택 |
|---|---|
| 언어 | Python 3.13 (`venv` + `pip`) |
| 임베딩 / 생성 | Ollama `bge-m3` / `gemma3:4b` |
| 벡터 검색 | `numpy` 전수 코사인 (158청크 규모라 근사 색인 불필요) |
| 키워드 검색 | `rank_bm25` |
| 파싱 / UI | `pymupdf`, `python-docx` / `streamlit` |

## 실행

Ollama가 설치되어 있고 `http://127.0.0.1:11434`에서 동작해야 합니다.

```bash
ollama pull bge-m3          # 1.2GB
ollama pull gemma3:4b       # 3.3GB

python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt

.venv\Scripts\python.exe data\make_samples.py   # data/src -> data/raw (선택: 이미 커밋돼 있음)
.venv\Scripts\python.exe -m src.ingest          # 색인 생성 (CPU 약 2분)
.venv\Scripts\python.exe -m streamlit run app.py
```

색인(`data/index/`)은 재생성 가능한 산출물이라 커밋하지 않습니다. 문서를 바꾸면 `src.ingest`를 다시 실행하세요.
한글 출력이 깨지면 `PYTHONIOENCODING=utf-8`을 붙입니다.

### 검증

```bash
.venv\Scripts\python.exe -m unittest discover -s tests   # 단위·회귀 테스트 72건
.venv\Scripts\python.exe eval\check_gold.py              # 질문셋 정답 근거가 문서에 실재하는지
.venv\Scripts\python.exe -m eval.eval_retrieval          # 검색 평가
.venv\Scripts\python.exe -m eval.eval_generation         # 생성 평가 (CPU 약 40분)
```

## 한계

솔직히 적어 둡니다. 이 프로토타입을 그대로 운영에 쓰면 안 됩니다.

- **속도** — CPU 전용(i5-1335U, GPU 없음)에서 체감 21~35초입니다. 15초 목표는 GPU 없이 도달 불가로 결론 났습니다. 프롬프트 처리(prefill)가 지연의 대부분이라, 근거 수를 줄이는 것 말고는 손댈 곳이 없습니다.
- **오답 노출** — `gemma3:4b`가 근거를 잘못 읽고 사실처럼 답하는 사례가 남아 있습니다(평가 43문항 중 3건). `gemma3:12b`에서는 0건이었으나 이 PC에서는 중앙 71초라 운영 불가였습니다. 모델 크기 문제로 보고 있습니다.
- **출처 검증의 빈틈** — 숫자가 없는 답변의 출처 오류는 걸러내지 못합니다.
- **평가 표본이 작습니다** — 질문 43개, 청크 158개입니다. 실제 사내 문서(수백~수천 쪽)에서는 수치가 내려갈 수 있어 문서를 바꾸면 다시 측정해야 합니다.
- **범위 밖** — 개인 데이터 조회, 인증, HR 담당자 기능, HWP 파싱을 지원하지 않습니다. 사내 배포에는 최소한 인증과 HWP 파싱이 필요합니다.

## 라이선스 주의

생성 모델 `gemma3:4b`는 [Gemma 이용약관](https://ai.google.dev/gemma/terms)을 따릅니다.
사내 사용을 금지하는 조항은 없지만, 웹이나 API로 제공하면 "배포"로 간주되어
이용 제한 조항과 약관 사본을 전달할 의무가 생깁니다(1.1(b), 3.1). 도입 전 법무 확인이 필요합니다.
